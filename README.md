# 分镜资产工作台

本机网页应用：把 Markdown 分镜整理成可编辑、有版本的角色、地点、道具和镜头资产。

使用参考：[提示词编写与避坑](docs/提示词编写经验与避坑.md)、[MiniMax H3 提示词指南](docs/MiniMax-H3-提示词指南.md)。

## 安装与启动

### 1. 安装运行环境

完整功能以 **Windows 10 / 11** 为运行环境：密钥加密使用 Windows DPAPI，打开媒体所在位置也依赖 Windows。准备以下工具，并确保它们已加入 `PATH`：

- [Git](https://git-scm.com/downloads)：下载和更新代码。
- [Node.js 24](https://nodejs.org/en/download)：自带 npm 和本项目使用的 SQLite，无需另装数据库。
- [FFmpeg](https://ffmpeg.org/download.html)：需要同时安装 `ffmpeg` 和 `ffprobe`，用于媒体校验、抽帧与音频处理。Windows 下载解压后，将包含这两个程序的 `bin` 目录加入 `PATH`，再重新打开终端。

在 PowerShell 中检查：

```powershell
git --version
node --version
npm --version
ffmpeg -version
ffprobe -version
```

### 2. 下载并安装依赖

```powershell
git clone https://github.com/aniongrey/storyboard-studio.git
cd storyboard-studio
npm ci
```

`npm ci` 按仓库中的 `package-lock.json` 安装依赖，不依赖上级目录的 `node_modules`。本项目无需构建。

### 3. 启动工作台

```powershell
npm start
```

保持终端开启，在浏览器打开 [http://127.0.0.1:4318](http://127.0.0.1:4318)。也可双击项目根目录的 **启动工作台.cmd**；按 `Ctrl+C` 停止终端中运行的服务。

首次启动会自动创建 `data/`，并导入 `examples/` 中的演示分镜和因果剧本。仓库不包含原机器的作品库、已生成媒体、下载、制作输出、作品截图或本机专用制作脚本；现有本地文件不会因 Git 忽略规则被删除。

### 4. 按需配置生成服务

浏览、导入和编辑分镜无需配置付费服务。需要生成时再配置：

- **RunningHub 视频**：在侧栏「设置」打开「接口与工作流设置」，保存自己的 RunningHub API Key，再核对工作流、素材和参数。
- **因果剧本 AI**：进入「因果剧本」→「LLM 设置」，选择服务商并填写模型与接口地址；使用本地 Ollama 时无需 API Key。
- **Fish Audio 语音**：在「接口与工作流设置」中配置自己的 Fish Audio Key 与音色。当前实现默认使用 `http://127.0.0.1:7890` 代理，可通过 `FISH_AUDIO_PROXY` 指定代理地址。
- **Codex 图片交付**：配合当前 Codex 会话生成图片，再按工作台的文件任务说明登记结果；仅编辑和管理已有素材不需要 Codex。

密钥通过网页交给本机后端并由 Windows DPAPI 加密保存，不随仓库提供。换电脑或 Windows 账户后，在页面重新配置自己的密钥。

### 可选设置与更新

在同一个 PowerShell 窗口设置环境变量后启动，例如端口被占用时：

```powershell
$env:PORT = '4319'
npm start
```

| 环境变量 | 用途 | 默认值 |
| --- | --- | --- |
| `PORT` | 本机服务端口 | `4318` |
| `STUDIO_DATA_DIR` | 作品数据目录，建议使用绝对路径 | 项目根目录下的 `data/` |
| `CODEX_PATH` | 可选的 Codex 可执行文件路径 | 本机 Codex 默认安装位置 |

`npm start` 不自动读取 `.env`；双击启动脚本会读取。若手动使用本地 `.env`，运行 `node --env-file-if-exists=.env server/main.mjs`。`.env` 已被 Git 忽略。

更新前停止服务并备份自己的完整数据目录，再执行：

```powershell
git pull --ff-only
npm ci
npm start
```

数据目录不纳入 Git；不要通过清空 `data/` 来更新应用。正式使用时只运行一个后端进程。

## 已实现

- 首次启动导入示例：6 个角色、6 个地点、14 个候选道具、8 场剧情、45 镜、160 秒。
- 当前作品下可新增和选择集数，已有内容默认第1集。镜头列表、分镜表、故事板与粗剪预览共用集数选择，角色、地点、道具全剧共用。导入时可追加到指定集；CLI 使用 `--append-to <projectId> --episode <集数>`（先在网页新增该集）。自动成组和顺序生成遵循所选集数，故事板不跨集。
- 网页上传分镜、保留原文和来源行号、显示待确认问题。相同内容重复上传去重；异源同名文件先显示差异，不覆盖人工编辑。
- 编辑角色、地点、道具与镜头；文本版本持久保存，可恢复旧设定。镜头可调整顺序。
- 上传 PNG/JPEG/WebP/MP4/WAV/MP3 绑定候选，图片、视频和音频分别采用；图片须小于 30 MB（保守按 30,000,000 字节，网页、导入与视频提交前共用校验），视频/音频本地上传上限仍为 60 MiB。旧媒体版本保留，超限旧图不能再上传至视频接口。格式和大小依据 [RunningHub 资源上传文档](https://www.runninghub.cn/runninghub-api-doc-en/api-425761099) 与 [官方高级示例](https://www.runninghub.ai/runninghub-api-doc-en/doc-8287470)，新上传页未另列尺寸/像素约束。角色音色可在媒体页直接试听，原文件名和音频规格一并保留。
- 从当前设定组合完整提示词，编辑最终全文，明确选择参考素材；图片任务先准备发送预览，视频任务则在“核对提示词”区确认后一键生成。编辑内容或参考变化后，旧快照与核对状态失效。
- Codex 图片文件任务：完整任务说明预览、固定目录交付、刷新校验并登记、重复刷新去重。
- RunningHub H3：后端直连、完整节点与参考槽位配置、**多参考 / 首尾帧两档工作流**、生成前核对实际请求、**可配置视频并发上限**（1–32，默认 1，可一键读取账号并发上限）、提交去重、taskId 续查、流式下载与解码检查。提交不明不自动重提，可核对后补录 taskId。
- **视频转参考**：侧栏独立入口，上传小于 30 MB 的 MP4，可选深度、骨骼、混合参考，支持一次输出多种。使用 [视频转参考工作流](https://www.runninghub.ai/zh-cn/call-api/api-detail/2116011399369904130?apiType=5) 的标准实例，沿用本机密钥、并发限制和任务恢复；同一文件与参数复用已有任务。源文件、请求快照和原生结果保存在 `data/video-references/<jobId>/`，不绑定或覆盖当前作品、集数与镜头。结果只下载与记录文件校验和，不播放、探测或解码，下载后由用户审看。失败或下载中断时在任务卡点击“重查 / 重下载”，只续查已有 taskId，不重新收费提交。
- 镜头列表逐镜顺序自动生成视频，默认原生 720p，音频仅作角色音色参考；已有故事板入口和历史媒体保留。队列维持并发上限，可暂停 / 继续 / 取消，逐项显示状态、taskId 与失败原因。
- 导出含采用媒体相对路径、提示词和版本的选用清单。
- 镜头工作台新增「分镜表」：逐镜查看画面、动作、景别、运镜、对白与计划时长，按搜索词和场次筛选；点缩略图或「预览」查看本镜已采用的图片 / 视频，可逐镜翻看并回到原编辑器。没有采用素材的镜头也保留，候选素材不会冒充采用版。
- 镜头工作台可切换「粗剪预览」：只收录已有采用素材的镜头，按镜头顺序连续播放，视频用自身时长、静帧按计划剪辑时长驻留，支持播放/暂停、逐镜跳转、静音与一键回到编辑器。
- 因果剧本工作台（导航「因果剧本」）：固定结果 + 因果事件图 + 人物认知时间线 + 剧情债务 + 剧情实验室；校验时间线、前提依据、认知来源与债务顺序，删改事件前先算下游影响；可导出**能被本工作台直接导入**的 Markdown，或一键发布成新作品。外接 OpenAI 兼容模型（密钥 DPAPI 加密在本机后端）。见 [docs/因果剧本工作台.md](./docs/因果剧本工作台.md)。

## 原视频镜头与比对分析

导航「原视频镜头」提供「镜头编辑 / 比对分析」两个视图。一条记录是一个镜头，可填写标题、运镜、画面内容及对应工作台镜号；时间点用逗号分隔，或在播放器定位后点本镜「加入当前时间点」，不会拆成多个镜头。保存保留原文、填写顺序和版本历史。

「比对分析」在顶部选择时间点，原视频与 AI 生成图等大并排对齐，镜头标题、运镜和详情放在图片下方。运镜与详情（原画面内容）可直接修改，停止输入约 0.6 秒或离开输入框后自动保存，底部显示保存状态，失败时保留修改，可点「保存镜头」重试。自动保存沿用当前集的镜头记录与版本历史；配图选择、实际提示词和检查记录折叠显示。原帧由本机 FFmpeg 从已保存原视频按点提取，不修改源视频。生成图从本集对应镜头或所属故事板的已登记图片中明确选择，不猜测最新图，也不自动采用。旧图不可用、对应镜号改变或原视频更换时提示复核。

保存后可「复制逐时间点生图任务」交给 Agent；生成与逐对检查后，通过原保存接口登记每个时间点的图片引用、检查状态及说明。复制任务不会启动收费生成，配对不会自动认定检查通过。

## 镜头列表制作视频（当前流程）

在「镜头列表」选择镜头并打开「生成视频」，或点击「顺序自动生成视频」批量逐镜提交。默认使用 H3 多参考与原生 720p，每镜沿用计划时长；本镜或关联资产须有已采用的画面参考，不要求创建故事板或四宫格。

角色音频只提供音色，视频依据文字台词生成对白，不复制样本台词、时间线或背景声。自动组合的镜头提示词移除旧 `Audio reuse: fully_copy` / `full_copy` 声明，原始分镜与历史任务快照保留。单镜临时编辑的区域原样进入其可见预览，不在提交时隐藏改写。

批量队列使用已保存的镜头设定、全局提示词勾选偏好及已采用素材；未勾选任何有内容的区域时阻塞，避免发送空提示词。会话内临时提示词编辑或手动素材选择请用单镜生成。默认范围跳过已有采用视频，缺少画面参考的条目跳过；时长超限或素材超出槽位时阻塞，不静默舍弃。旧故事板可在相应视图继续使用。

## 四宫格故事板（已有功能）

在「镜头工作台」点击「创建故事板」，选择起始镜头，将四个连续且尚未成组的镜头组成一组。切换「故事板」查看；组内顺序对应左上、右上、左下、右下，可在「四镜头与设置」调整格位或更换成员。

- 组只保存1至4个连续镜头的引用，不复制剧情，2×2未使用的格子留纯白。每组最多3个不同说话角色，同一角色重复说话只占一个音色槽。在组内修改画面、动作、对白、运镜、时长或关联资产并保存，直接更新原镜头，四宫格与组视频的提示词同步生成。原始 Markdown 和导入的视频提示词全文继续保留。
- 「生成四宫格」显示自动生成的完整提示词，先准备预览，再创建当前 Codex 会话的图片任务。可参考本组四镜头与关联资产的图片；结果交付、刷新、候选与采用沿用原流程。也可在组的媒体页上传已有四宫格，绑定时记录当前剧情版本，请自行核对上传图内容。
- 「生成视频」只用多参考模式，本组已采用四宫格固定占参考图1，相关角色的已采用图片默认勾选，最多共6张参考图。对白角色已采用音色按首次发声顺序全部选择，不再按台词长短省略音色。旧分组超过3个说话角色或漏选已采用音色时阻止提交并要求处理。视频提示词只描述有效镜头，明确忽略空格并在最后一镜结束；具体音色效果仍需样片验证。
- 生成时长默认取四镜头计划之和，**不静默截短**。不符合当前工作流的整数秒范围时必须调整；手动设置组生成时长后，四镜头时间按原计划占比分配，不改原计划。额外生图/视频要求统一在组设置中编辑，不单独改写派生提示词全文。
- 任一成员镜头、关联资产、项目设置、格位或额外生图要求改变后，旧四宫格标记过期；视频生成前必须重新生成或绑定并采用当前版本。任务冻结四镜头版本，生成期间的修改不会伪装成旧任务成果；旧媒体始终保留。仅更改额外视频要求不会让四宫格过期。
- 整段视频归故事板采用和导出。粗剪中已有采用视频的组覆盖其四个原镜头，只播放一次；尚未采用组视频时继续使用原镜头的采用素材。选用清单同时包含组、成员顺序和实际播放序列。

自动成组每组最多4个连续镜头、3个不同说话角色；加入第四个说话角色会从该镜开始下一组。片尾不足四格留白，不重复引用前组镜头。未导入音色的说话角色仍计入上限；单镜超过3个说话角色须先拆分。已有分组和媒体不自动重排。移动原镜头时不能拆散已建立的组。

## 自动成组与顺序自动生成视频

镜头工作台标题右侧有「⇥ 从这一镜自动成组」和「▶ 顺序自动生成视频」两个入口。

**自动成组**从一个起始镜头往后走，按上述镜头数和说话角色上限分组，跳过已经成组的镜头。单镜说话角色超限会明确阻塞整批创建，不丢弃镜头或音色。提交前显示实时计划预览，整批一次性建组，任一组不合法则整批回滚。

Markdown导入会读取项目根目录的 `AGENTS.md`，保存 `agentInstructions` 规则快照，CLI导入结果也会输出这些规则。后续 Agent 先读当前短入口，制作任务再使用本机 `$storyboard-studio` 技能，只加载相关流程；历史快照和规则不混入画面或对白提示词。

**顺序自动生成视频**是把一批故事板交给队列依次生成，并由后端保持在并发上限内的多个任务同时跑：

- **入队前提是已有「采用」的四宫格图片**：没有采用四宫格、或四宫格基于旧剧情/旧顺序已过期、或该组已有采用视频（可勾选“允许重做已有视频”覆盖）的组会被跳过，并在面板里列出跳过原因。跳过不是失败——其余组照常排队。一个都不满足时直接拒绝，不创建空队列。
- **Key 不可用时不排队**：未配置 RunningHub Key，或本机读不出密钥（例如 DPAPI 不可用）时整队拒绝并提示去“接口与工作流设置”重存一次，避免逐组撞上同一个错误刷出一堆失败记录。
- **点一次就持续生成**：队列始终维持到并发上限个任务在跑，某个任务完成后立刻补下一个，直到整批结束。不需要反复点按钮。
- **并发上限**取「本机设置」与「账号并发上限」中较小者；点击“读取账号并发数”会调 RunningHub `queue/status` 取回该 Key 的最大并发数，只用于“不超过”，不会把本机设置顶大。本机设置可在“接口与工作流设置 → 视频并发上限”里改（1–32，默认 1）。
- 面板逐组显示状态（待提交 / 准备中 / 已提交 / 生成中 / 已完成 / 失败 / 阻塞 / 跳过）、RunningHub taskId 与错误原因，并提供刷新状态、暂停、继续、取消、跳转“生成任务”。“取消”只停止提交新任务，已在远端跑的任务保留可继续查询下载。
- 每组视频都用**本组已采用的四宫格作参考图 1**（节点 `141`），实际对白角色的采用音色按首次发声顺序绑定音频槽 `144/160/189`；超过三个说话角色或漏选已采用音色时阻止提交，需先拆组或处理引用，不按对白量舍弃音色。结果只成为候选，仍需手动采用。
- 远端明确拒绝并发（HTTP 200 但 `code 421`）时不算失败：远端没有创建任务，本机只留一条可辨识的失败记录，队列会把该组放回待提交并退避重试，避免误报与重复计费。若提交结果不明（可能已计费）则立即暂停队列，等你在 RunningHub 后台核对后再继续。

## 图片生成：当前 Codex 会话

1. 选中角色、地点或镜头，打开“生成图片”。
2. 检查或编辑完整提示词，选择参考图，点击“准备发送预览”。
3. 点击“创建 Codex 生图任务”，把完整任务交给当前 Codex 会话，或让 Codex 执行 `node scripts/pending-jobs.mjs`。
4. Codex 用内置图片工具生成，将真实输出交付到指定目录；可用 `node scripts/deliver-image.mjs --job <jobId> --image <图片绝对路径>`。
5. 网页点击“刷新资产”。结果先作为候选，点击“采用”后才成为选定参考。

目前这是明确的文件交付模式：网页创建任务不会自动向当前聊天发送消息。CLI 未登录不影响此模式。App Server 自动生图入口尚未开放，避免声称已经支持未验证的工具调用前校验。

## 视频与配置

在“接口与工作流设置”保存 RunningHub Key。Windows 使用当前用户 DPAPI 加密，保存在 `%LOCALAPPDATA%\StoryboardStudio\runninghub.dpapi`，不在项目目录或浏览器 localStorage。仅后端读取；Agent 子进程不继承密钥环境。

视频页提供两种生成方式，各对应一个已核对的 RunningHub H3 应用，节点号互不相同：

- **多参考素材**（默认）：工作流 ID `2084320751339032577`，21 个默认节点参数，最多 6 张图 + 3 段音色，图片依次绑定 `141/142/143/161/175/176.image`，比例与时长都可调（1–30 整数秒）。
- **首尾帧**：工作流 ID `2084282198664007682`，8 个默认节点参数，只有首帧（图1）与尾帧（图2）两个图片槽，没有比例节点（输出比例跟随首帧），另有「像素/百万」参数（0.2–2.0），时长 5–15 整数秒。尾帧开关关闭时就是单图生视频。

**图2 不会留空**：该工作流的 `143` 是 LoadImage，空槽会让整个工作流跑不起来（应用作者也写了「要关开关，别删图片」）。所以只要没明确选尾帧，图2 就复用首帧那一份上传文件——同一份文件只上传一次，开关按关闭下发，不会被当成首尾同帧的静态片。明确选了两张图才是真正的首尾帧（开关开启）。

两档都沿用 LoRA 强度为 0、不覆盖工作流有效模型名的默认值，也都不含测试示例素材；参考槽位配置完整后即可提交，提交只表示发起这次生成，不代表这组参数已经成功出片。切换生成方式会重置槽位绑定——`143` 在多参考档是参考图3、在首尾帧档是尾帧，节点号含义不同，不能串用。

**实例规格**在“生成参数”区用下拉选择，两档共用：`default`（标准 24G，默认）/ `plus`（48G）/ `ultra`（84G）。规格越高单价越高，按实际需要选。浏览器中上一版留下的 48G 配置首次载入时改为标准 24G，已有 ultra 选择保留，此后保留手动选择；手动生成、自动队列和提交脚本默认一致。也可在“高级工作流配置 · JSON”里修改 `instanceType`，非法值会在生成前被拒绝。

故事板的“生成参数”和“本次参考素材”可展开、折叠。“最终提示词 · 实际发送内容”统一编辑和核对本次发送全文，未填写时显示组合提示词；只修改最终提示词时，点击“生成视频”会先保存再提交。带 `<Subject n> (Sx)` 标签的最终提示词按原镜头首次发声顺序识别角色，音频换槽或取消后会同步主体音色、音色保持要求及对白前的引用；取消音频保留台词，改用独立音色。前端显示和后端发送共用同步逻辑，原镜头与历史生成快照不变。其他组设置或原镜头有未保存修改时，先到“镜头与设置”保存。

“生成 H3 结构与运镜草稿”使用正式英文字段、主体与音频标签、`(Sx)` 说话人编号和 `<d>[Chinese] ...</d>` 对白标签，并补充未填写的运镜。无法确认的说话人会提示先修正。源中文描述保留，需由 AI 整理为英文描述；既有最终提示词不会自动迁移。

故事板的视频自动关联与批量队列共用规则：只自动选择本组已采用四宫格和明确对白角色的已采用音色，音色按首次发声顺序分配。转述、配文和无对白角色不自动选择音色；图片候选与其他镜头图片不自动混入视频引用。手动增加素材时本组四宫格仍占参考图 1，超过槽位上限会阻止生成，不静默丢弃。

故事板已采用四宫格不校验图片的剧情版本或镜头顺序。修改对白、动作或组内顺序后，单组与批量视频生成仍可使用原已采用图片。发送预览生成之后的内容、采用选择或文件变更仍需要重新准备预览。

提示词编写与排错经验见 [故事板提示词编写经验与避坑](docs/提示词编写经验与避坑.md)，包含实际发送文本、H3 标签、说话人与音色编号、无对白镜头、运镜和运行版本问题，并区分已实现修复与尚未试片的建议。

媒体页每张图片、视频和音频卡片均可点击“打开本地文件位置”，在本机 Windows 资源管理器中选中该媒体文件。文件已移动或删除时会显示错误提示，不改变媒体采用结果。

在“镜头工作台”点开一个镜头，详情默认进入 **生成视频** 页（不再是设定编辑页），标签栏会明确标出当前所在页。**生成时长是可改参数**：本镜没手动改过时，用设定编辑里的计划剪辑时长当默认值；改过就一直用改过的值（按镜头记住，刷新后仍在），改回计划值即恢复为默认。改这里只影响本次生成，不会改动计划剪辑时长。时长上限按生成方式取值（1–30 / 5–15 整数秒，见下），超出或留空会阻止提交。手动生成、首尾帧和自动队列均默认原生720p；9:16会请求0.9百万像素，预计原片736×1280，按32像素网格取整，保留实际原片而不放大或裁切。已保存的清晰度选择与自定义像素保留；预设清晰度对应的像素预算会同步计算。画面比例只在多参考档可调。

默认选中本镜已采用图片和关联角色/地点/道具的采用媒体；没有采用图时不会悄悄改用候选。角色形象与音色合组，可一起勾选。分镜列表只显示本镜媒体，前后端均禁止引用其他镜头的媒体。参考视频功能暂未对接，参考列表中不显示视频格式素材。多参考档保留 3 张图 + 3 段音频槽位；首尾帧档只保留首帧与尾帧两个图片槽，音频与视频都不进（选中非图片素材会被后端拒绝）。超限素材必须手动取消或调整，不静默丢弃。

提示词按 subject_definitions、summary、retention_analysis、detailed_description、overall_soundscape、non_diegetic_music，以及风格、构图、运镜、情绪、转场、时长比例分区。各区可展开编辑，初始全部不选；勾选偏好保存到本机数据库，全作品共用、重启后保留。文字编辑仅保留当前网页会话的本镜；恢复设定按钮可重新生成各区。仅已勾选且非空的内容进入最终提示词。Subject 将同一角色的 Picture 与 Audio 归到一起，占位编号与实际槽位一致；首尾帧档的图片占位改用 `<First frame>` / `<Last frame>`，不编号（该档只有两个固定槽）。首尾帧档还会在「转场」区追加一句要求描述首帧到尾帧的画面变化，并把「时长与比例」区的比例行换成 `Output ratio follows the first frame.`。

确认实时拼接全文及参考素材后，直接点击“生成视频”（不再需要勾选核对项）。视频页已取消单独的“准备发送预览”步骤：点击生成时由后端一次完成校验、参考素材上传与提交，未能通过时会就地列出待处理项。提交成功后**留在本镜页面，不再跳到“生成任务”**；视频页底部“本镜最近一次视频任务”给出状态、RunningHub taskId、结果链接，以及“刷新状态 / 查看生成任务 / 重查·重下载”，本页不自动轮询，需要最新进度时点“刷新状态”或进“生成任务”。未使用槽位发送 None，不复制图片填满；供应商对空槽及音色的实际支持仍需样片验证。普通操作无需编辑 JSON；高级配置可展开。

比例和时长直接传给 RunningHub：多参考档写 `115.aspect_ratio` 与 `186.value`，首尾帧档写 `135.value`。两档都可调整原生生成像素：多参考写 `147.value`，首尾帧写 `142.value`，范围0.2–2.0；首尾帧比例跟随首帧。原生清晰度480p/720p/1080p会按当前比例选择足够的像素预算，9:16分别为0.4/0.9/2.0，预计原片480×864、736×1280、1088×1920。计算在前端、后端与队列共用；新任务不再进行本机缩放。若比例下2.0仍达不到目标（例如21:9的1080p），预览直接阻塞。回片按真实原片尺寸验收；不足目标时保留原片并将任务标为未达标，不登记成功媒体、不自动重提收费。升级前已经冻结的旧resize任务仍可按原快照恢复。

依据：[该RunningHub工作流作者的像素尺寸表](https://www.runninghub.ai/zh-cn/ai-detail/2084320751339032577)、[ComfyUI ResolutionSelector源码](https://github.com/Comfy-Org/ComfyUI/blob/master/comfy_extras/nodes_resolution.py)。像素单位按1024²计算、尺寸取最近32倍数；预计尺寸不等于已完成真实付费试片，最终以原片验收为准。

首尾帧工作流里有一个“仅Zip输出”节点，默认关闭。如果把它打开，RunningHub 只回一个压缩包；本工作台不自动解压，会在任务结果处直接说明未能取到可下载视频，并提示改回关闭该节点或手动下载压缩包。

生成视频按钮会先上传明确选中的参考素材并校验，**校验阶段不会提交收费生成**；校验通过后同一次点击才调用收费接口。结果、费用与错误以服务端实际返回为准。现有成功记录只验证过旧默认示例的 10 秒配置，本作品的新参考配置还需一个样片验证。

WAV 音色可在多参考档的视频参考列表选择，并明确绑定 `144.audio`、`160.audio` 或 `189.audio`。这里只登记音色参考并保留实际上传标识，不代表已验证节点用途或声音克隆效果。图片任务仅接受图片参考。首尾帧工作流没有音频节点，切到该档后参考列表只提供图片。参考视频（`164.video`）功能暂未对接，因此不在页面暴露。

手动提交时，在跑的视频任务数已达到视频并发上限（默认 1）会被拒绝并返回 409，不创建第二个任务；要并行提交请先在“接口与工作流设置 → 视频并发上限”里调高。未知提交结果仍需先核对 RunningHub 任务记录：已有 taskId 可补录续查；确认没有本次任务才关闭不明状态，再发起新的操作。

## 粗剪预览

在“镜头工作台”页标题右侧切换「▤ 镜头列表 / ▶ 粗剪预览」。粗剪预览是只读的连续播放：按镜头顺序把**已经采用素材**的镜头串起来，用来快速判断节奏与衔接，不生成新文件、不改动任何采用结果。

- 收录范围：采用图或采用视频任一存在的镜头；两个都没有的镜头不出现，只有采用音频的镜头也没有画面可放，因此同样不收录。空序列会给出引导，指回「媒体」页去采用素材。
- **本段是图还是视频**由采用素材的 `kind` 判定，两种状态各自成立：视频段用播放器控件，静帧段用自己的进度条与倒计时。
- **画面比例跟着本段媒体自己走**，不套用作品比例：采用视频按视频尺寸（含横屏）、采用四宫格/静帧按图片尺寸，元数据缺尺寸时等元素报出真实尺寸再校正，都取不到才退回作品比例。舞台宽度按「画面高度上限 × 本段比例」反推，因此竖幅不会被压出黑边、横屏也不会被挤在窄框里。
- 时长口径：采用视频按视频自身时长播放，采用静帧按本镜计划剪辑时长驻留；两者都取不到时退化为 3 秒。视频时长与计划不一致时，播放区下方会给出提示，但不会改写计划剪辑时长。
- 播放控制：播放/暂停、上一镜、下一镜、从头播放、静音，右侧点选序列中的任意一条即可跳转。「在编辑器中打开」会切回列表视图并选中该镜头。播放区获得焦点后支持空格播放/暂停、左右方向键换镜。
- 视频段的播放器是 [Plyr](https://github.com/sampotts/plyr)（MIT，本地文件在 `public/vendor/plyr/`，图标 sprite 也指向本地，不联网）：可播放/暂停、拖动进度、看时间、调音量、画中画、全屏。控件条在播放中会自动收起，鼠标移入或暂停时显示。**这里是同一根时间轴的两种操作方式**：在播放器里暂停等于粗剪暂停，拖动进度后粗剪的剩余时间与进度条立刻跟随；空格与方向键仍然归粗剪序列（播放器自己的键位已关闭）。视频段画面上的细进度条不显示，进度由播放器自己的进度条表示。
- 离开粗剪预览（切到列表、其他导航或「在编辑器中打开」）会立即停止播放循环，不会在后台继续走时间。
