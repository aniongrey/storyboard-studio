# 因果剧本工作台（StoryForge）

2026-10-17 落地。入口在工作台左侧导航「▸ 因果剧本」，服务地址与工作台同一个：<http://127.0.0.1:4318>。

## 它解决什么问题

工作台原来从「已经写好的分镜稿」开始，这个模块把起点前移一步：先钉住**不能改的结果**，再倒推**必须成立的条件**，让每个事件都能被上游事实解释、被下游事件消费。产出仍然是一份符合导入格式的 Markdown，直接回到分镜工作台继续生成。

判断口诀：**结果倒推条件，条件变成事件，事件留给下一集当条件。**

## 页面结构

| 区域 | 作用 |
| --- | --- |
| 顶栏 | 项目标题与简介、切换剧本、保存状态、模型状态、项目设定 / LLM 设置 / 重新分析 / 导出并发布；统计收在单行概况栏 |
| 左栏 · 故事资料 | **目标与约束**、**人物与欲望**分标签浏览，资料在栏内滚动 |
| 中栏 · 剧本工作区 | **因果图 / 剧集时间轴 / 剧情债务 / 剧情实验室 / 分镜稿与导出**分标签切换；图页保留连线工具、图例和底部剧集快速跳转 |
| 右栏 · 事件与辅助 | **事件编辑 / 校验 / 人物状态 / AI 助手**分标签切换。事件编辑保留所有字段，分镜与状态、台词、角色认知、债务按需展开 |

界面以 2560×1440 桌面为主要设计尺寸，三栏在首屏内各自浏览，不再把长编辑表单堆在画布下方。点击事件或跳转剧集会打开右侧事件编辑；人物状态中的「编辑本集认知记录」直接展开对应认知编辑区。布局切换不改事件坐标和作品数据。

## 数据模型（`server/forge.mjs`）

- 固定结果 `outcome`：`episode / title / detail / lock(hard|soft|open) / nodeId / mechanism`。硬锁定是「不允许改」的锚点，AI 提示词里也明确禁止改它。
- 事件 `node`：`episode / title / goal / preconditions[] / actors[] / motive / action / result / stateChanges[] / beats[] / foreshadow / knowledge[] / dialogue[] / outcomeId / debtIds[] / x / y`。
- 连线 `edge` 四种：`cause` 直接因果、`requires` 必要前提、`motive` 动机影响、`payoff` 伏笔回收。
- 剧情债务 `debt`：`question / planted[] / payoff[] / status`。债务不是待办，而是「观众已经看见、还没得到回答」的问题。
- 分支 `branch`（剧情实验室）：`draft / merged / discarded`，不污染正式图。
- 规范化：所有写入都过 `normalizeProject()`，非法枚举回落、越界集数夹取、指向不存在对象的引用清空（id 至少 3 个字符，否则会重新生成——测试里踩过）。

## 校验规则（确定性，不调模型）

`analyze()` 只做能验证的事，语义判断交给模型：

- `TIME_ORDER` 时间线颠倒（下游比上游早）
- `PRECONDITION_GAP` 前提在上游语料里几乎没出现过（双字覆盖率 < 0.2，仅提示）
- `PRECONDITION_NO_EDGE` 写了前提但没有任何入边（且上游存在）
- `KNOWLEDGE_UNSOURCED` 人物知道了上游没发生过的事（「未卜先知」）
- `DEBT_ORDER` / `DEBT_UNPAID` 回收早于埋设 / 尚未兑现
- `NODE_UNLINKED` 孤立事件，`EPISODE_EMPTY` 空集汇总
- `stats`：事件数、硬锁定数、错误 / 提示数、覆盖率、`scriptFresh`（分镜稿是否与因果图一致）

`analyzeImpact(project, nodeId, patch|null)`：删除或改动事件前先算下游波及范围、失效前提、受影响的固定结果与债务，返回 `affected / outcomes / debts / missing / suggestions`。界面删事件时先弹这张影响单再确认。

## AI 六项功能（`server/forge-ai.mjs`）

| task | 界面名字 | 做什么 |
| --- | --- | --- |
| `result-planner` | 结果规划师 | 从一个固定结果倒推出事件链草案（未配置模型时退回 `localPlans` 的三种本地方案：利益与规则冲突 / 误会与信任崩塌 / 保护他人的两难） |
| `causal-architect` | 因果构造师 | 补两个事件之间的中间事件与必要前提 |
| `character-simulator` | 人物模拟器 | 站在某个人物已知的信息上，判断他会怎么选 |
| `script-reviewer` | 剧情审查员 | 语义层面的动机、节奏、重复问题 |
| `lab-explore` | 剧情实验室 | 给同一事件三条其他发展路线，确认后才合并 |
| `storyboard-writer` | 分镜编剧 | 把事件字段写成工作台能导入的分镜稿，存进 `project.script` 并带指纹 |

模型结果永远是建议：先落成卡片，点「采纳 / 插入 / 合并」才写进因果图。`project.script.fingerprint` 与当前因果图不一致时，导出自动退回确定性模板，不会把过期分镜稿当成正稿。

## 外接 API 设置

**密钥只留在本机后端**，浏览器永远拿不到原文。

- 界面：顶栏「LLM 设置」→ 选服务商（ollama / deepseek / doubao / openai / gemini / groq / xai / custom）、模型、接口地址、API Key、温度；可「测试连接」「读取模型列表」。- 存储：设置 `data/settings/llm.json`，密钥 `data/settings/llm.dpapi`（Windows DPAPI 加密，只有同一个 Windows 账户能解）。
- 环境变量优先（适合临时换模型，不写盘）：`FORGE_LLM_PROVIDER` `FORGE_LLM_BASE_URL` `FORGE_LLM_MODEL` `FORGE_LLM_TEMPERATURE` `FORGE_LLM_API_KEY`。
- 请求走 OpenAI 兼容的 `POST {baseUrl}/chat/completions`，`response_format: json_object`；个别服务商不支持该字段时自动去掉重试一次。
- 本地 ollama 不需要 Key，默认 `http://127.0.0.1:11434/v1`。
- 必须填 Key 的服务商没填时，AI 接口返回 409 `LLM_KEY_MISSING`，界面提示去设置里补，不会静默失败。

## 导出与发布

导出和发布走同一条 `buildExport()`，不会出现两份不一样的文本：

1. `GET /api/forge/projects/:id/export?from&to` 预览 / `?download=1` 下载 `.md`
2. `POST /api/forge/projects/:id/publish` 直接生成一份工作台里的分镜作品

命令行（不必开网页）：

```bash
node scripts/export-forge.mjs                                   # 导出当前工程的 1..末集到 outputs/
node scripts/export-forge.mjs --from 1 --to 12 --out outputs/前12集.md
node scripts/export-forge.mjs --file examples/storyforge-龙娘部落.json --publish
```

`--publish` 会把导出的 Markdown 直接导进工作台（新作品），等同于点「发布到分镜工作台」。

## 导入格式契约

导出严格沿用工作台既有的六段结构，`server/importer.mjs` 可直接解析：

```
# 《片名》分镜提示词
## 一、项目元数据
## 二、风格总设定
## 三、角色设定库        ### 角色N：名字 + ```json```
## 四、场景设定库        ### 场景A：名字 + ```json```
## 五、完整分镜提示词    ### 第N场：标题 + #### 镜头 001-A｜标题 + 九项字段
```

`test/forge.test.mjs` 里有断言：导出的 Markdown 必须能被 `parseMarkdown()` 解析，场次数、镜头数、角色数与导出统计一致。

## 示例工程

`examples/storyforge-龙娘部落.json`：20 个事件 / 26 条连线 / 7 个固定结果（4 个硬锁定）/ 3 项剧情债务 / 2 个实验室分支，覆盖《F级废物？我在禁区建立龙娘部落》第 1–30 集。导出结果：20 场、122 镜、约 530 秒、7 角色、6 场景，校验 0 错误 3 提示（空集是真的空）。

首次启动时若 `forge_state` 为空会自动灌入，删掉工程不会重新灌。

## 验收清单

- `node --test test/forge.test.mjs test/forge-http.test.mjs`：领域规则 9 项 + HTTP 面 1 项。
- 界面：导航「因果剧本」→ 20 个节点、26 条连线渲染完成；右栏三个标签、底栏四个标签都能切换；控制台无异常。
- 导出：`node scripts/export-forge.mjs --file examples/storyforge-龙娘部落.json --publish --data-dir <临时目录>` 能成功导入（20 场 / 122 镜）。

## 已知边界

- 参考视频仍不对接，人物一致性靠 `visualPrompt` 文本 + 工作台的角色资产。
- 校验的文本比对是双字覆盖率，只用来兜底；真正的「这句前提讲不讲得通」要靠剧情审查员。
- 分镜稿由模型写过后，只要因果图再改一个字，`scriptFresh` 就变 false，需要重新跑「分镜编剧」；这是刻意设计，避免导出过期内容。
